# v0.2.0 忠实移植记录

v0.1.0 曾将 57 个顶层技能压缩为 8 个入口。用户明确要求忠实原版后，本版恢复全部原名技能、完整正文和配套资源，不再采用精简工作流。

## 来源与数量

- 仓库 `https://github.com/cursor/plugins`，目录 `pstack`。
- 上游版本 `0.15.30`，提交 `8b3326d99fd4b993cb33a24dad8af03175c642c5`。
- 184 个原文件全部保存在 `upstream/pstack.zip`，逐文件摘要在 `upstream/lock.json`。
- 57 个顶层技能保持原名，另加一个 `$pstack` 到 `$poteto-mode` 的薄入口。
- 23 个工作流完整保留。
- Benny 的 3 个技能保持休眠形式；完整自动化包、模板及参考文件均保留。
- 2 个原版代理角色提示保留，交由当前 Codex 委派能力读取，不冒充原生注册的代理类型。

## 逐文件变化

`migration.json` 记录每个原文件的目标路径、原始摘要和生成后摘要。`port_upstream.py --check` 会从快照重新计算预期内容，发现漏文件、正文删改、脚本改动和可执行权限变化。

| 文件类型 | 变化 |
|---|---|
| 顶层 SKILL.md | 原名、描述、完整正文保留；移除 Codex 不使用的前置信息；正文前增加适配说明链接 |
| 调用策略 | 原 `disable-model-invocation: true` 转成 `agents/openai.yaml` 中的 `allow_implicit_invocation: false` |
| `paths`、`icon`、`color` | 原始值保存在快照；不伪装成 Codex 路径触发器或界面配置。TypeScript 的使用范围仍保留在原描述中 |
| 原版代理提示与 Benny 启动文件 | 保留原文，只增加适配说明链接 |
| README | 完整原文放到 `docs/UPSTREAM_README.md`，只修正因移动产生的相对链接；根 README 说明 Codex 安装 |
| 原版插件元数据与 gitignore | 保存在 `upstream/metadata/`；Codex 使用单独的清单和忽略规则 |
| worktree-audit.sh | 默认 Cursor 历史目录改为显式 `PSTACK_TRANSCRIPTS_DIR`；缺少历史时用 `review-no-history`，不推断候选安全 |
| 其他脚本、指南、参考文件、图片、锁文件、测试、示例 | 保留原始字节与可执行标记 |

没有删除原版 make-bot-ui、Benny、编排 CLI、PR 监控器或形式化验证工具。文件存在不代表其外部服务和运行环境已经可用。

## 执行层差异

[Codex 适配说明](harness/codex.md) 集中处理原文中的 Cursor 工具名称、模型角色、规则路径、代理类型、上下文读取和外部操作授权。原文继续保留这些词，便于与源文件直接比较。

保留原版的设计探索、独立审查、步骤列表、显式批准及验证要求。宿主不支持的必需步骤必须说明未完成，不能用自审冒充独立审查，不能用本地文件冒充运行中的自动化，也不能自动缩短流程。

当前系统、开发者、用户和仓库指令优先。适配层不增加发送消息、创建工单、提交、推送、合并或部署的授权。已授权的任务继续执行，不重复索取许可。

## 安装方式变化

v0.1.0 复制各技能目录。完整原版存在指向包外层的相对引用，因此 v0.2.0 复制完整包，再把顶层技能目录以相对符号链接注册。完整副本位于发现目录的同级存储，不会把 Benny 的休眠技能重复注册为全局入口。

旧安装记录仍可识别。更新前检查本地修改和名称冲突；成功后移除旧版精简入口。更新、失败回滚、项目移动和休眠文件保留均有测试。

实际 Codex 加载检查发现，完整包的插件清单会使技能名带上 `codex-pstack:` 前缀。原技能名和目录不变；README 使用实际名称示例。加载检查也验证了原版折叠式多行描述的保留，避免只搬运 `description: >-` 标记而丢失内容。

## 后续维护

工程内容应在上游快照和明确的变换规则中维护。不要直接编辑生成的原版正文后把它描述为忠实副本。需要跟进新上游时，先取得明确提交，重建快照与摘要，再检查生成差异和运行验证。

本版仍保留了原版流程中的强制步骤和工具前提。没有通过减少流程来降低成本。使用者可以按当前任务决定是否启用这些技能，但移植本身不代替使用者改写方法。
