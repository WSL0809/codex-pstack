# v0.2.0 验证记录

来源为 pstack `0.15.30`，固定提交 `8b3326d99fd4b993cb33a24dad8af03175c642c5`。

## 已完成

- 快照包含 184 个原始文件；每个文件由摘要和权限记录约束。
- 57 个顶层技能和 3 个休眠技能的完整原版正文保留；生成校验会拒绝正文删改。
- 58 个顶层入口通过 Codex skill-creator 自带的 `quick_validate.py`。验证器在 `uv run --with pyyaml` 的隔离依赖环境运行；安装器不依赖 PyYAML。
- 19 项 Python 测试通过。包含 v0.1.0 升级、完整资源保留、休眠技能不注册、相对链接移动、名称冲突、修改保护、普通异常回滚、缺少历史时的 worktree 保留，以及多行技能描述的保留。
- 原版 Bun 工具在临时副本中运行。Bun `1.4.4` 按原锁文件安装依赖，68 项编排、PR 监控和计划检查测试通过，TypeScript 类型检查通过。
- 原版状态图测试用 Node `v26.8.2`、本机 Java 25 和 TLC `2.19` 运行。macOS 上 61 项通过、5 项失败、1 项跳过。4 个失败涉及 `/var` 与 `/private/var` 的路径别名，另 1 个失败涉及 Linux `LD_PRELOAD` 故障注入。PID namespace 场景因平台限制跳过。原版测试文件保持不变。
- 把 `TMPDIR` 设为其真实路径后，单独重跑上述 4 个路径场景，4 项全部通过。此结果不等同于 macOS 全套测试通过。

## 安装与适配检查

- 本机已从真实的 v0.1.0 用户安装升级到 v0.2.0。旧的 7 个专项入口已移除，完整包资源和 58 个目录链接已安装。
- Codex CLI `0.160.0` 的实际 `skills/list` 在当前工作区及独立临时目录中，均发现 58 个用户级入口，全部启用。实际主入口为 `$codex-pstack:pstack`。此检查不发起模型请求。
- 独立审查核对了源文件保留、安装与卸载、旧记录迁移、兼容层及包校验，没有报告需要修复的问题。其后，实际 Codex 发现检查暴露了多行描述解析问题；转换器已修复，并增加回归测试。

## Linux CI

CI 使用 Python 3.9 和 3.13 检查包与安装器，另用 Node 26、Bun 1.4.4、Java 17 和 TLC 2.19 运行原版工具测试。当前提交的实际结果以仓库 Actions 为准；工作流配置本身不代表测试通过。

## 边界

这些检查证明源文件保留、静态结构及已执行路径。它们不证明全部 57 个工作流在真实业务任务中的表现。

没有验证 Cursor 云服务、Grok Bot、Slack/工单自动化、Benny 触发器、Bugbot 发起操作或生产部署。文件和流程已保留，外部能力仍需单独配置及授权。

未验证 Windows 和所有 Codex 客户端版本。安装被强制终止或机器断电后的恢复仍需检查锁、暂存备份和记录。
