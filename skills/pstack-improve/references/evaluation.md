# Evaluate a workflow change

Define the behavior the change should improve, a few observable criteria, the cost limit, and the acceptance rule before running candidates. Use realistic tasks and isolated workspaces. Compare the same inputs under the baseline and revised skill.

Keep candidate requests natural. Do not tell a candidate which hidden behavior is graded or ask it to recite the rules it followed. Keep evaluation labels and preferred outcomes out of candidate-visible file names and prompts. An independent judge can see the rubric but should not see model or variant identity.

Use agents only when authorized. Without independent execution, perform a documented manual walkthrough and label it as such; do not call it a blinded experiment. An evaluation does not authorize external publication, live service mutations, or unbounded spend.

Inspect actual artifacts, commands, and permitted execution traces. Self-reported compliance is not evidence. Compare correctness, scope control, verification quality, time, and cost where measured. A small trial can find a failure mode but cannot establish a universal quality gain. Repeat across representative tasks before promoting a broad rule.
