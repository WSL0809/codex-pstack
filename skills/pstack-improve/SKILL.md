# Improve

Read [the Codex adapter](../pstack/references/codex.md). Distinguish an analysis request from authorization to change the repository or global skills. Use only the current task history and relevant accessible project records.

Group demonstrated recurring mistakes into classes. Prefer fixing each class at the highest level that works:

1. Remove the wrong path through architecture, single ownership, or one authoritative representation.
2. Reject invalid states with types or a lint/CI check that names the repair.
3. Test the observable contract. Demonstrate failure on a representative past mistake.
4. Write an instruction only for the judgment that cannot be encoded.

Explain why the selected level is appropriate. Keep changes within the requested scope. If rule documentation is useful, pair each rule with its enforcement mechanism. Remove obsolete rules once their mistakes cannot occur.

For a retrospective, produce accepted lessons, rejected generalizations, and deferred structural work with evidence. Apply edits only within the user's request. Do not automatically create tickets or send team messages.

For skill authoring or personal workflow extraction, read the available skill-creator guidance. Use real examples from this task. Prefer editing an existing focused skill over creating another catchall. Keep conditional details in references. Do not convert one incident into an unconditional global rule. For a behavioral comparison, read [evaluation](references/evaluation.md).
